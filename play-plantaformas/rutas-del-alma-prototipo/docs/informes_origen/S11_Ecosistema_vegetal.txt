## 0. RESUMEN EJECUTIVO

El nuevo arte **resuelve el 90 % del hueco visual del jardín** señalado en el GDD. Ya no es necesario dibujar malezas y flores "por código" ni usar movimiento simulado: el paquete incluye el ciclo de vida completo, tres niveles de zarza con identidad cromática propia, la enredadera puente segmentada, partículas y —lo más valioso— **auras de reacción a la luz integradas en el propio sprite**.

**Decisión de arquitectura:** este arte debe reemplazar *en bloque* el sistema provisional de plantas del prototipo, **antes** de tocar los personajes. El jardín es el corazón del Nivel 1 y ahora es lo primero que puede verse "de producción".

## 2. ESPECIFICACIONES DE INTEGRACIÓN

### 2.1 Anchor point y línea base
- **Todos los sprites de planta deben anclarse en la base central (raíz)**, no en el centro geométrico. La hoja ya respeta una línea base visualmente constante en las filas 1, 2, 3 y 6.
- **Excepción:** la enredadera (fila 4) se ancla en la **base izquierda** para el segmento de arranque y en **ambos extremos** para el arco (ver 2.4).
- Verificación: superponer en Aseprite/Photoshop los frames de una misma animación; la raíz no debe moverse más de 2 px.

### 2.2 Resolución y escalado
- El arte está en Hi-Bit (detalle alto). La resolución lógica del juego es 480×270.
- **Regla:** escalar con `image-rendering: pixelated` / `nearest neighbor`. **Nunca** usar `bilinear` (destruye el Hi-Bit).
- Tamaño de render sugerido: zarzas ≈ 48–64 px de ancho en escena; flores ≈ 24–32 px; enredadera ≈ 96–128 px de ancho por arco.
- Si el sprite original es mayor, **pre-escalar en la build**, no en tiempo de ejecución (evita parpadeo sub-píxel).

### 2.3 Transparencia
- La hoja tiene fondo blanco. Antes de integrar, el desarrollador debe **extraer el alfa real** (el blanco no es transparente en el PNG de origen).
- **Método recomendado:** `remove.bg` o script `ImageMagick` con `-fuzz 15% -transparent white`, seguido de revisión manual de los bordes oscuros de las zarzas (el halo blanco residual es el bug que ya tuvimos con la cabaña).
- **Criterio:** al colocar un sprite sobre el fondo nocturno del lago, no debe verse ningún píxel blanco.

## 3. SISTEMA DE CAPAS DE ILUMINACIÓN (la clave del arte)

El arte ya incluye, en la **fila 6**, las reacciones a la luz. Esto cambia la arquitectura del Sprint 6:

### 3.1 Estrategia: "sprite con aura integrada" en lugar de "shader puro"
En vez de calcular el *rim light* con código, el desarrollador debe usar **dos capas por planta**:
```
Capa A: sprite base (sin aura)
Capa B: sprite con aura (misma posición, alpha modulado)
```
- **Estado normal:** Capa A visible al 100 %, Capa B oculta.
- **Luz de Liam (dorado):** Capa B (aura dorada) aparece con `alpha` interpolado 0→1 en 0,3 s. Se superpone con `globalCompositeOperation = 'lighter'`.
- **Luz de Elara (violeta):** Capa B (aura violeta) con el mismo método.
- **Ventaja:** el artista ya decidió *dónde* brilla la planta; el código solo enciende la capa. Menos shader, más fidelidad.

### 3.2 Mapeo de auras (fila 6)
| Sprite con aura | Se activa con | Efecto narrativo |
| :--- | :--- | :--- |
| Flor naranja + aura dorada | Luz de Liam | Revela el "hecho" (centro luminoso) |
| Flor violeta + aura violeta | Luz de Elara | Revela la "emoción" (halo) |
| Zarza verde + aura dorada | Luz de Liam | Muestra la raíz débil (ZB-01) |
| Zarza roja + aura roja | Luz de Liam | Muestra la gema/rizoma (ZB-02) |
| Zarza morada + aura violeta | Luz de Elara | Muestra el humo que se libera (ZB-03) |
| Zarza morada + aura negra | Luz de Liam | Contracción de espinas (alivio) |
| Brote + aura dorada | Cualquier luz | "Promesa" (la planta responde) |

### 3.3 Cooldown de encendido
Para no "quemar" el efecto, el aura debe tener **respiración** (oscilar entre alpha 0,7 y 1,0 con un `sin(t)`), no quedarse fija al 100 %.

## 4. ANIMACIONES DERIVADAS DEL ARTE ESTÁTICO

El arte es estático por estado, pero el juego necesita movimiento. **No se piden nuevos frames**; se generan con código sobre los sprites existentes:

| Animación | Método sobre el sprite | Parámetros |
| :--- | :--- | :--- |
| **Idle (respiración)** | Escala Y 1.00↔1.03 + offset Y ±1 px | Periodo 2,5 s, `ease-in-out` |
| **Viento** | Rotación ±3° alrededor del anchor (raíz) | Periodo 3 s, desfase por planta (semilla aleatoria) |
| **Brote (CV-03→CV-04)** | Crossfade entre sprites + scale-in desde 0,8 | 0,8 s |
| **Floración** | Crossfade capullo→flor + "pop" de escala 1.0→1.1→1.0 | 0,5 s |
| **Marchitamiento** | Crossfade flor→marchita + tint a gris progresivo | 1,5 s |
| **Arranque (zarza)** | Shake violento (offset X ±3 px, 4 frames) + fade-out + partículas de la fila 5 | 0,4 s |
| **Rebrote (marchita→zarza)** | Crossfade marchita→ZB-01/02/03 + shake de entrada | 1,0 s |

**Regla anti-"bailarín":** el offset de la respiración se aplica **arriba del anchor**, nunca en el centro, para que la raíz quede clavada al suelo.

## 6. LA ENREDADERA PUENTE (fila 4) — Mecánica del lago

La fila 4 da **7 estados de crecimiento**, perfectos para el "puente de enredadera" del Sprint 5:

```
Estado 0: montículo con brote (col 1)
Estado 1: tallo corto curvado (col 2)
Estado 2: tallo en "S" (col 3)
Estado 3: tallo extendido (col 4)
Estado 4: arco formándose (col 5)
Estado 5: arco completo (col 6)
Estado 6: arco con hojas densas (col 7) = PUENTE TRANSITABLE
```

**Reglas de código:**
- El puente se construye **proceduralmente**: cada estado se posiciona interpolando entre el ancla de origen y el destino (una losa del lago).
- Solo el **Estado 6** tiene plataforma física (`collision = true`); los estados 4–5 son visuales.
- Crecimiento: 1 estado cada ~1,5 s → puente completo en ~10 s (coherente con el Sprint 5).
- Si Aides no está en el equipo, el puente **no crece** (fallback del Sprint 10: losas autoiluminadas).

## 7. VARIANTES EMOCIONALES (fila 6) — Integración con el Sprint 8

La fila 6 no son "estados emocionales de la planta", son **reacciones a la luz**. Para los estados de Aides (Serenidad/Ansiedad/Melancolía/Alegría) se aplica **color grading por código** sobre los sprites de las filas 1–3:

| Estado de Aides | Tint aplicado al jardín | Partícula extra |
| :--- | :--- | :--- |
| Serenidad | Ninguno (color puro) | Mariposas naranjas |
| Ansiedad | Desaturación 25 % + tinte rojizo en zarzas | Humo gris |
| Melancolía | Tinte azulado + brillo 0,8 | Humo negro lento |
| Alegría | Saturación +15 % | Destellos dorados + mariposas moradas |

**Importante:** el tint se aplica a un `Container`/`Group` de plantas, no a cada sprite individual (rendimiento).

## 8. ESPECIFICACIÓN DE GUARDADO (localStorage)

```javascript
gardenData = {
  plants: [
    { id: "p01", x: 240, y: 180,
      type: "thorn", level: 2,        // ZB-02
      state: "growing",               // idle|growing|ready|wilted
      elapsed: 42.3,                  // tiempo en estado
      aura: null                      // null|liam|elara|both
    },
    { id: "p02", x: 310, y: 180,
      type: "flower", color: "gold",  // FL-01
      state: "ready", elapsed: 12.0
    }
  ],
  vines: [ { id: "v01", from: "shore", to: "slab3", stage: 4 } ],
  particles: "runtime"                // NO se guardan
}
```
- `elapsed` se congela al cerrar (regla del Sprint 4: el tiempo de juego activo, no real).
- `aura` se persiste para que, al recargar, la reacción a la luz no "parpadee" de nuevo.

## **Integración de los recursos gráficos del «Jardín de la Mente» en el videojuego *Rutas del Alma***



Especificación de implementación

Escenario 2D · Canvas



**Objetivo:** integrar los tres conjuntos de recursos gráficos que has aportado para construir el escenario jugable del Jardín de la Mente, con sus elementos ambientales, vegetación, arquitectura, agua, iluminación y objetos interactivos.

La decisión técnica más importante es que **no debemos introducir las imágenes completas como fondos únicos**. Los recursos deben convertirse en elementos gráficos independientes que el motor pueda colocar, ordenar, animar y activar durante la partida.

# **2. Tratamiento de las tres láminas**

## **Lámina 1: separar y preparar los recursos**

La primera lámina está organizada por categorías y contiene etiquetas de identificación.

El desarrollador debe solicitar al artista una exportación de los elementos individuales.

| Categoría original        | Tratamiento para el juego               |
| ------------------------- | --------------------------------------- |
| Árbol Ancestral           | Objeto ambiental independiente          |
| Cascada                   | Fondo rocoso y agua animable            |
| Puente de Piedra          | Estructura independiente                |
| Arco Monumental           | Estructura y portal por separado        |
| Lago Mágico               | Superficie, reflejos y flores separados |
| Flores Flotantes          | Objetos independientes                  |
| Rocas                     | Variantes reutilizables                 |
| Zarzas y Rosas            | Elementos decorativos y obstáculos      |
| Vegetación Principal      | Recursos individuales                   |
| Plantas y Arbustos        | Variantes independientes                |
| Flores Decorativas        | Recursos individuales                   |
| Enredaderas               | Elementos ambientales                   |
| Setas y Elementos Mágicos | Recursos independientes                 |
| Suelo y Terreno           | Piezas de construcción del nivel        |
| Elementos Interactivos    | Objetos con comportamiento              |
| Elementos de Fondo        | Recursos con parallax                   |
| Efectos Mágicos           | Animaciones y partículas                |

**Importante:** las etiquetas que aparecen en la lámina sirven como referencia de catálogo, pero no deben formar parte de los recursos finales del videojuego.

## **Lámina 2: composición y colocación**

Esta lámina permite establecer la composición general del escenario.

El desarrollador debe utilizarla como referencia de distribución, no como fondo definitivo.

Se recomienda separar:

- Árbol y lámpara.
- Cascada y rocas.
- Lago y flores flotantes.
- Puente.
- Arco monumental.
- Zarzas y rosas.
- Vegetación inferior.
- Camino de piedra.

Cada elemento debe conservar su escala relativa y su posición de referencia, pero podrá desplazarse para adaptarse al diseño jugable.

## **Lámina 3: biblioteca de variaciones**

Esta lámina es especialmente útil para desarrollar la continuidad de los escenarios.

Contiene recursos que pueden servir para crear distintas condiciones ambientales:

- Cielo nocturno.
- Atardecer.
- Cielo diurno.
- Aurora.
- Tormenta.
- Nubes.
- Sol y lunas.
- Estrellas y destellos.
- Montañas y bosques.
- Árboles de diferentes colores.
- Variaciones de cascadas y estructuras.
- Flores y vegetación.
- Efectos luminosos.

El desarrollador debe preparar un sistema de selección de recursos para que el escenario pueda cambiar su ambiente sin reconstruirse desde cero.

**No se deben activar todos los recursos de la tercera lámina simultáneamente:** son alternativas y variaciones, no una única composición obligatoria.

# **3. Sistema de capas y orden de dibujo**

Esta es una de las partes más importantes de la implementación.

El escenario debe renderizarse en un orden controlado para evitar que las flores, el agua, las rocas o los personajes aparezcan detrás de elementos incorrectos.

Orden recomendado:

| Orden | Capa                   | Contenido                                                                   |
| ----- | ---------------------- | --------------------------------------------------------------------------- |
| 0     | Cielo                  | Cielo nocturno, luna y estrellas                                            |
| 1     | Fondo lejano           | Montañas y siluetas de bosque                                               |
| 2     | Fondo intermedio       | Árboles lejanos, vegetación y estructuras distantes                         |
| 3     | Arquitectura posterior | Puente, rocas de fondo y cascada                                            |
| 4     | Terreno                | Suelo, plataformas y caminos                                                |
| 5     | Elementos ambientales  | Árbol, arbustos y vegetación                                                |
| 6     | Agua                   | Lago, superficie y reflejos                                                 |
| 7     | Objetos interactivos   | Flores especiales, lámparas y objetos mágicos                               |
| 8     | Personajes             | Liam, Elara y Aides                                                         |
| 9     | Primer plano           | Rocas, plantas y elementos que pueden ocultar parcialmente a los personajes |
| 10    | Efectos                | Brillos, partículas, destellos y magia                                      |

El orden real debe poder configurarse por objeto. Por ejemplo, una flor puede estar delante del personaje o detrás de él dependiendo de su posición.

## **3.1. Parallax**

Se recomienda incorporar movimiento parallax para crear profundidad.

```

const parallaxLayers = [
  { name: "sky", speed: 0.02 },
  { name: "mountains", speed: 0.08 },
  { name: "distantForest", speed: 0.15 },
  { name: "middleVegetation", speed: 0.35 },
  { name: "foreground", speed: 0.75 },
  { name: "ground", speed: 1.0 }
];

```

Estos valores son iniciales de referencia y deben ajustarse mediante pruebas visuales. El terreno jugable debe permanecer sincronizado con la cámara.

## **4.1. Colisiones y terreno**

No utilizar la transparencia de los PNG para determinar automáticamente las colisiones.

El desarrollador debe definir las colisiones mediante datos independientes:

- Plataformas transitables.
- Superficies de apoyo.
- Zonas de caída.
- Obstáculos.
- Áreas de interacción.
- Límites del escenario.

Ejemplo:

```
const jardinCollisionMap = {
  platforms: [
    {
      id: "camino_principal",
      x: 0,
      y: 310,
      width: 1600,
      height: 30
    }
  ],
  obstacles: [],
  interactionZones: [],
  exits: []
};
```

Las coordenadas son ilustrativas, no corresponden a una medición definitiva de los artes.

El artista y el desarrollador deben acordar la altura del terreno y la escala de los elementos antes de cerrar la composición final.

# **5. Animación de los elementos**

No es necesario animar todos los recursos. Hay que identificar cuáles aportan vida y cuáles deben permanecer estáticos.

| Elemento         | Animación recomendada                      |
| ---------------- | ------------------------------------------ |
| Árbol Ancestral  | Movimiento sutil de hojas y pequeñas luces |
| Lámpara          | Oscilación y pulsación de luz              |
| Cascada          | Ciclo de agua y espuma                     |
| Lago             | Ondulación y reflejos                      |
| Flores Flotantes | Balanceo y movimiento sobre el agua        |
| Flores mágicas   | Apertura, cierre y brillo                  |
| Vegetación       | Balanceo suave                             |
| Enredaderas      | Movimiento ocasional                       |
| Zarzas           | Movimiento sutil o reacción al acercarse   |
| Setas luminosas  | Pulsación de intensidad                    |
| Arco Monumental  | Brillo progresivo al activarse             |
| Partículas       | Movimiento independiente                   |

## **5.1. Estados de animación**

Cada recurso animable debe disponer de estados definidos.

Ejemplo para una flor:

```
const flowerStates = {
  closed: "cerrada",
  growing: "creciendo",
  blooming: "florecida",
  illuminated: "iluminada",
  dormant: "inactiva"
};
```

El desarrollador debe relacionar estos estados con el sistema de juego existente, sin crear una lógica paralela.

## **5.2. Cascada y agua**

La cascada debe tener, preferiblemente, tres componentes:

1. Fondo de agua y rocas.
2. Animación del agua descendiendo.
3. Espuma y partículas de salpicadura.

El lago debe separarse en:

1. Base del agua.
2. Ondulación.
3. Reflejos.
4. Nenúfares.
5. Flores flotantes.

De esta forma se pueden animar los componentes independientemente y mantener un rendimiento razonable.

# **6. Sistema de iluminación y efectos mágicos**

Los recursos de la tercera lámina permiten preparar un sistema común de efectos.

El desarrollador debe crear un gestor de iluminación que controle:

- Color.
- Intensidad.
- Radio de luz.
- Velocidad de pulsación.
- Duración.
- Estado de activación.
- Relación con el personaje.

Ejemplo conceptual:

```
const magicalLights = [
  {
    id: "lampara_arbol",
    color: "#FFB52E",
    intensity: 0.85,
    radius: 90,
    pulse: true
  },
  {
    id: "flor_luminosa",
    color: "#FFD84A",
    intensity: 0.65,
    radius: 45,
    pulse: true
  }
];
```

Los valores son orientativos y deben calibrarse visualmente.

**Importante:** el brillo no debe formar parte inseparable de todos los PNG. Cuando sea posible, conviene tener el recurso base y su iluminación en capas separadas.

Esto permitirá cambiar la intensidad, apagar la luz o modificar el efecto según los acontecimientos del juego.

# **10. Adaptación al motor actual del videojuego**

La integración debe respetar el funcionamiento del prototipo existente.

Como referencia de la auditoría anterior del juego:

- Renderizado mediante Canvas 2D.
- Resolución lógica de visualización de 480 × 270.
- Mundo horizontal de aproximadamente 3200 × 360.
- Proyecto inicialmente concentrado en un único HTML.

Por tanto, la implementación debe considerar dos escalas:

**Escala de diseño:** resolución y dimensiones originales de los recursos gráficos.

**Escala de juego:** dimensiones a las que se representan dentro del mundo y en la pantalla.

No reducir los PNG originales a 480 × 270. El motor debe escalarlos según su posición, tamaño y cámara.

# **11. Rendimiento y optimización**

El escenario contiene muchos recursos con transparencia, vegetación y efectos luminosos.

Hay que evitar que cada elemento cree operaciones de renderizado innecesarias.

Requisitos:

- Cargar las imágenes al inicializar el escenario.
- Evitar cargar PNG continuamente durante el juego.
- Reutilizar recursos repetidos.
- Limitar las partículas simultáneas.
- Evitar múltiples capas de brillo excesivas.
- Renderizar las capas estáticas en superficies auxiliares cuando resulte conveniente.
- Mantener las animaciones independientes de la tasa de refresco.
- Descargar recursos que ya no sean necesarios al abandonar el escenario.
- Mantener la calidad visual en pantallas de diferentes dimensiones.

Los fondos estáticos pueden agruparse en una superficie auxiliar, pero los elementos que necesitan movimiento o interacción deben permanecer independientes.

# **12. Fases de implementación para el desarrollador**

## **Plan de desarrollo del Jardín de la Mente**

1. Fase 1 · Preparación

   **Auditoría de los recursos**
   - Inventariar las tres láminas.
   - Identificar todos los elementos.
   - Comprobar transparencia y resolución.
   - Detectar elementos duplicados.
   - Definir los recursos que faltan.
   Entregable: inventario de recursos.
2. **Fase 2 · Separación gráfica**
   - Obtener cada recurso individual.
   - Eliminar etiquetas.
   - Revisar bordes y transparencia.
   - Separar luces y efectos.
   - Preparar versiones animables.
   Entregable: biblioteca de PNG.
3. **Fase 3 · Composición del escenario**
   - Colocar cielo y montañas.
   - Situar árboles y estructuras.
   - Integrar cascada y lago.
   - Colocar vegetación.
   - Construir el terreno.
   Entregable: escenario estático completo.
4. **Fase 4 · Terreno jugable**
   - Definir plataformas.
   - Crear colisiones.
   - Configurar obstáculos.
   - Establecer zonas transitables.
   - Comprobar el recorrido de los personajes.
   Entregable: escenario explorable.
5. **Fase 5 · Animación ambiental**
   - Animar cascada.
   - Añadir movimiento al lago.
   - Animar flores y plantas.
   - Incorporar partículas.
   - Añadir iluminación dinámica.
   Entregable: escenario vivo.
6. **Fase 6 · Interacciones**
   - Integrar objetos especiales.
   - Vincular las lámparas.
   - Incorporar las interacciones de Aides.
   - Comprobar estados de crecimiento.
   - Verificar la compatibilidad con las reglas actuales.
   Entregable: escenario funcional.
7. **Fase 7 · Integración y QA**
   - Probar cámara.
   - Revisar escala.
   - Verificar rendimiento.
   - Comprobar colisiones.
   - Revisar todos los efectos.
   - Comprobar guardado y continuidad de partida.
   Entregable: versión integrada y validada.

# **15. Decisiones que debe tomar el desarrollador antes de empezar**

Hay tres cuestiones técnicas que conviene cerrar con el equipo:

1. **¿Los recursos originales están disponibles por separado?** Si solamente tenemos las láminas compuestas, habrá que hacer un proceso de extracción y limpieza antes de integrarlos.
2. **¿El escenario se recorrerá horizontalmente?** La implementación debe mantener la lógica de cámara y terreno que ya utiliza el juego.
3. **¿El arco monumental será una salida, un punto de interacción o un elemento decorativo?** Su comportamiento debe quedar definido por el diseño narrativo antes de programarlo.

## **Instrucción final para el desarrollador**

La implementación del Jardín de la Mente debe utilizar las tres láminas gráficas aportadas como biblioteca de recursos y referencia de composición.

No se debe insertar ninguna de las láminas completas como único fondo del escenario.

El trabajo consiste en separar, organizar, preparar e integrar los recursos individuales mediante un sistema de capas 2D en Canvas.

El escenario debe permitir desplazamiento de cámara, parallax, animación ambiental, iluminación mágica, colisiones y objetos interactivos.

Se debe conservar el funcionamiento del motor actual, la lógica de los personajes y las mecánicas existentes.

La primera entrega debe contener el escenario completo, el terreno jugable y una selección de elementos animados e interactivos. La ampliación de recursos se realizará después de validar esta primera integración.

La arquitectura debe permitir reutilizar el sistema de composición en futuros escenarios de Rutas del Alma, sin duplicar el motor ni crear un sistema independiente para cada nivel.

**Mi recomendación de gestión:** antes de pedir al desarrollador que integre todo, solicitarle primero un inventario de recursos con tres estados: «disponible», «requiere separación o limpieza» y «pendiente de creación». Así sabremos qué trabajo corresponde al artista y cuál al programador, y evitaremos que el desarrollador tenga que reconstruir elementos gráficos que ya existen.

Además, como el juego ya dispone de una resolución lógica de 480 × 270 y un mundo horizontal, conviene comprobar la composición a esa escala desde la primera prueba, no al final.
